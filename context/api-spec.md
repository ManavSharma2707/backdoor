# API specification

Base path `/api/v1`. JSON in and out. OpenAPI generated by FastAPI is the machine contract. Frontend types are generated from it (`make openapi-types`). This file is the human contract. Roles: all endpoints require `owner` today, the dependency `require_role("owner")` is attached everywhere so other roles can be added later.

---

## 1. Conventions

| Topic | Rule |
|---|---|
| Auth | `Authorization: Bearer <access_jwt>` on everything except health, login, refresh, registration (if enabled), demo-login (if enabled) and `/jobs/*` (uses `X-Job-Token`) |
| Tenant | Always from the token. No endpoint takes `tenant_id` in path, query or body |
| IDs | UUID strings. `sale_lines` and movements use integer ids in responses |
| Money and quantity | Strings with fixed decimals (`"182340.00"`, `"12.500"`). Never JSON numbers |
| Dates | ISO 8601. Business dates as `YYYY-MM-DD`. Instants in UTC with `Z` |
| Pagination | `?page=1&page_size=50` (max 200). Response `{ "items": [...], "total": 123, "page": 1, "page_size": 50 }` |
| Sorting | `?sort=name:asc,created_at:desc`, whitelisted per endpoint, 422 on unknown field |
| Filtering | Plain query params per endpoint. Search is `?q=` |
| Idempotency | Header `Idempotency-Key` (8 to 64 chars) accepted on POSTs marked (I). Replays return the stored response with header `Idempotent-Replay: true` |
| Errors | One envelope, below |
| Rate limits | Login 10/min per IP, 5 failures per 15 min per account. Chat 20 messages/min and 200/day per user. Default 120/min per user. 429 with `Retry-After` |
| Request id | `X-Request-ID` echoed in responses and in the error envelope. A client value is kept only if it is 8 to 64 characters of letters, digits, dot, underscore or hyphen, otherwise a new id is made. OpenAPI and docs live at `/api/v1/openapi.json` and `/api/v1/docs` |
| CORS | Allowlist from `CORS_ORIGINS`. `Access-Control-Allow-Credentials` is not sent: the browser talks to the same origin through the Vercel rewrite, so the refresh cookie needs no CORS credentials. Exposed headers: `X-Request-ID`, `Idempotent-Replay`, `Retry-After` |

### Error envelope
```json
{ "error": { "code": "VALIDATION_ERROR", "message": "Quantity must be more than zero.",
             "details": [{"field": "lines[0].quantity", "issue": "must be > 0"}],
             "request_id": "8f1c..." } }
```
Codes: `VALIDATION_ERROR` 422, `UNAUTHENTICATED` 401, `FORBIDDEN` 403, `NOT_FOUND` 404, `METHOD_NOT_ALLOWED` 405, `CONFLICT` 409, `IDEMPOTENCY_MISMATCH` 422, `RATE_LIMITED` 429, `INSUFFICIENT_STOCK` 409, `BATCH_EXPIRED` 409, `RECEIPT_EXCEEDS_ORDER` 409, `RETURN_EXCEEDS_SOLD` 409, `PO_STATE_INVALID` 409, `REPORT_NOT_READY` 409, `MISSING_SUPPLIER_OR_COST` 409, `AGENTS_DISABLED` 503, `QUOTA_EXHAUSTED` 503, `INTERNAL` 500. Messages follow `ui-copywriting.md` (plain, no dashes, say what to do next).

## 2. Auth

| Method and path | Purpose | Notes |
|---|---|---|
| POST `/auth/login` | `{email, password}` -> `{access_token, expires_in, user, tenant}` and sets refresh cookie | Generic error on bad credentials. Lockout and rate limit. Audit |
| POST `/auth/refresh` | Uses cookie, rotates it, returns new access token | Requires header `X-Requested-With: backroom` and `Origin` check. Reuse detection |
| POST `/auth/logout` | Revokes current refresh token, clears cookie | |
| POST `/auth/logout-all` | Revokes every token family of the user | |
| GET `/auth/me` | Current user, tenant (name, type, is_synthetic), settings summary | |
| POST `/auth/change-password` | `{current_password, new_password}`, revokes other sessions | Policy in `security.md` |
| POST `/auth/register` | Creates tenant plus owner | Only when `ALLOW_REGISTRATION=true`, else 404 |
| POST `/auth/demo-login` | `{profile_key}` -> same as login | Only when `DEMO_LOGIN_ENABLED=true` and tenant `is_synthetic`. Rate limited |

Cookie: name `backroom_rt`, `HttpOnly`, `Secure` (off only when `APP_ENV=local`), `SameSite=Lax`, `Path=/api/v1/auth`, `Max-Age` 14 days.

| GET `/audit?action=&from=&to=&page=` | Owner audit view |

### SSE protocol
`Content-Type: text/event-stream`. Events (each `data:` is JSON):

| Event | Payload |
|---|---|
| `status` | `{ "text": "Checking your numbers" }` from a fixed list of friendly phrases only (never tool names or reasoning) |
| `token` | `{ "text": "partial answer text" }` |
| `block` | `{ "type": "table|chart|metric_cards|product_card|risk_list|download|action_card|followups", ... }` (schemas in `agents-spec.md`) |
| `source` | `{ "label": "Monday plan, 12 Oct", "ref": {...} }` |
| `ui_action` | `{ "type": "navigate|apply_filters|open_product|open_report_line|start_tour", ... }` validated against a whitelist |
| `done` | `{ "message_id": "...", "feedback_token": null }` |
| `error` | `{ "code": "QUOTA_EXHAUSTED", "message": "..." }` |

Send a comment line `: ping` every 15 seconds to keep proxies open. The frontend uses `@microsoft/fetch-event-source`. If `VITE_CHAT_DIRECT_URL` is set the stream goes straight to the Render URL with the bearer token (CORS allowlisted).

## 12. Contract tests

- Every route has a test for 401 without token.
- Every route that reads or writes tenant data has a two-tenant isolation test (tenant B token cannot see or change tenant A ids, returns 404).
- Error envelope shape asserted in one parametrised test.
- OpenAPI snapshot test fails when routes change without regenerating frontend types.
